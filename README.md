# MapOverlay — Emme4 반투명 지도 오버레이

Emme4 네트워크 편집 창 위에 사전에 캡처한 지도 이미지를 반투명하게 띄워두고,
필요할 때만 오버레이를 "편집 모드"로 전환해 위치/배율/투명도를 조절하는
AutoHotkey v2 스크립트입니다. Emme4 자체는 전혀 건드리지 않으며, 별도의
독립 실행 프로그램으로 동작합니다.

## 요구 사항

- Windows
- [AutoHotkey v2](https://www.autohotkey.com/) 설치 (v1과 호환되지 않으므로 반드시 v2 설치)

## 실행 방법

1. `MapOverlay.ahk`를 더블클릭해서 실행
2. 처음 실행 시 지도 이미지 파일(png/jpg/bmp/gif)을 선택하는 창이 뜸
3. 오버레이가 화면에 반투명하게 나타나며, 시작 시에는 "편집 모드" 상태

## 단축키

| 단축키 | 동작 | 비고 |
|---|---|---|
| `Ctrl+Alt+T` | 편집 모드 ↔ 클릭 통과 모드 전환 | 언제나 동작 |
| `Ctrl+Alt+H` | 오버레이 완전히 숨김 ↔ 표시 전환 | 언제나 동작 |
| `Ctrl+Alt+Q` | 설정 저장 후 종료 | 언제나 동작 |
| 좌클릭 드래그 (몸통) | 오버레이 위를 클릭한 채로 끌어서 이동 | 편집 모드에서만 |
| 좌클릭 드래그 (가장자리) | 오버레이 **모서리/변 근처(약 22px 이내, 상하좌우 어디든)**를 클릭한 채로 끌면 종횡비를 유지하며 크기 조정(반대쪽이 고정) | 편집 모드에서만 |
| 방향키 | 오버레이 1px 미세 이동 | 편집 모드에서만, 클릭 통과 모드에서는 Emme4로 그대로 전달됨 |
| `Shift + 방향키` | 오버레이 10px 이동 | 편집 모드에서만 |
| `Shift + 마우스휠` | **마우스 커서 위치를 기준으로** 확대 / 축소 (5% 단위) | 편집 모드에서만, 클릭 통과 모드에서는 Emme4로 그대로 전달됨 |
| `Ctrl+Alt+Up` / `Ctrl+Alt+Down` | 투명도 증가 / 감소 | 편집 모드에서만 |
| `Ctrl+Alt+O` | 다른 지도 이미지로 교체 | 편집 모드에서만 |
| `Ctrl+Alt+R` | 참조점 기반 반자동 정렬 시작 | 아래 참고 |
| `Ctrl+Alt+P` | 회전 기준점 지정 시작 | 아래 참고, 회전각 0도일 때만 |
| `Ctrl+Alt+[` / `Ctrl+Alt+]` | 기준점 중심으로 1도씩 반시계/시계 방향 회전 | 편집 모드, 기준점 지정 후 |
| `Ctrl+Alt+Shift+[` / `Ctrl+Alt+Shift+]` | 기준점 중심으로 10도씩 회전 | 편집 모드, 기준점 지정 후 |
| `Ctrl+Alt+0` | 회전 초기화(0도로 복귀) | 편집 모드 |
| `Ctrl+Alt+L` | 오버레이 고정 ↔ 고정 해제 | 언제나 동작 |
| `Esc` | 정렬/회전기준점 지정 진행 중 취소 | 진행 중이 아니면 무시됨(Emme4로 그대로 전달) |

**클릭 통과 모드**가 실제로 Emme4 네트워크 편집을 위한 모드입니다. 이 모드에서는
오버레이가 화면에 그대로 보이지만 모든 마우스 클릭/휠이 오버레이를 투명하게 통과해
아래의 Emme4 창으로 전달됩니다(`WS_EX_TRANSPARENT`).

**편집 모드**는 지도 위치/배율/투명도를 다시 맞출 때만 짧게 전환해서 쓰는 모드입니다.

**`Ctrl+Alt+T`(모드 전환)와 `Ctrl+Alt+H`(숨김/표시)의 차이**: `Ctrl+Alt+T`는 오버레이를
보이는 상태로 유지하되 클릭이 통과되게/안 되게 바꾸는 것이고, `Ctrl+Alt+H`는 편집 모드
여부와 무관하게 오버레이를 화면에서 아예 안 보이게 껐다 켰다 하는 것입니다. Emme4 화면을
완전히 깨끗하게 보고 싶을 때는 `Ctrl+Alt+H`를 쓰세요.

### 이동/확대·축소가 더 쉬워진 점 (개선 사항)

- **드래그 이동**: 오버레이 위 아무 곳이나 마우스로 누른 채 끌면, 마우스를 놓을 때까지
  실시간으로 창이 따라옵니다(이전 버전보다 훨씬 안정적으로 동작하도록 방식을 교체함).
- **방향키 이동**: 마우스 없이도 방향키로 1px, `Shift+방향키`로 10px씩 정밀하게 옮길 수 있습니다.
- **커서 기준 확대/축소**: 이전 버전은 항상 왼쪽 위 모서리를 고정한 채 커지고 작아져서
  원하는 지점을 맞추기 어려웠는데, 이제는 **마우스 커서가 가리키는 지점이 화면에서
  고정된 채로** 확대/축소되어, 정렬하고 싶은 지점 위에서 휠을 굴리면 그 지점 기준으로
  자연스럽게 비율이 조정됩니다.
- **가장자리 드래그로 크기 조정**: 오버레이 몸통이 아니라 **모서리나 변(사방 약 22px
  이내, 상하좌우 어디든)**를 클릭한 채로 끌면, 마치 사진 뷰어에서 크기조정 핸들을
  끄는 것처럼 반대쪽이 고정된 채로 종횡비를 유지하며, **지금 크기에서 끄는 방향
  그대로** 커지고 작아집니다. 몸통을 끌면 이동, 가장자리를 끌면 크기 조정으로 자동
  구분되며, 모서리뿐 아니라 변(예: 아래쪽 가장자리 전체)도 넓게 인식하므로 예전보다
  훨씬 잡기 쉽습니다.
- **드래그 반응성 개선**: 마우스가 실제로 움직였을 때만 창을 다시 그리도록 바꿔서,
  가만히 누르고 있을 때 불필요하게 반복 갱신되던 것을 줄였습니다(랙 완화).

## 스케일(줌) 동기화 방법

Emme4의 확대/축소 비율을 프로그램적으로 읽어올 방법이 없기 때문에(그게 가능했다면
onmap 문제 자체가 없었을 것), 두 가지 정렬 방법을 제공합니다.

### 방법 1: 수동 정렬

1. Emme4에서 네트워크를 원하는 배율로 확대/축소
2. `Ctrl+Alt+T`로 편집 모드 전환
3. `Shift+휠`로 오버레이 이미지를 Emme4 네트워크와 눈으로 맞춰 확대/축소, 드래그로 위치 정렬
4. `Ctrl+Alt+T`로 다시 클릭 통과 모드로 전환해 편집 재개

### 방법 2: 참조점 기반 반자동 정렬 (`Ctrl+Alt+R`)

지도 이미지와 Emme4 화면에서 같은 지점(교차로, 랜드마크 등) 2곳을 순서대로 클릭하면,
두 기준점 사이의 거리 비율로 배율을, 기준점 1의 위치 차이로 이동량을 자동 계산해
오버레이에 즉시 적용합니다. 기준점 2곳은 서로 멀리 떨어져 있을수록(예: 지도 좌상단과
우하단 부근의 교차로) 배율 계산 오차가 줄어듭니다.

1. `Ctrl+Alt+R` 입력 → 자동으로 편집 모드로 전환되고 정렬 절차 시작
2. **정렬 1/4**: 지도 이미지 위에서 기준점 1(예: A 교차로)을 클릭
3. **정렬 2/4**: 지도 이미지 위에서 기준점 2(예: B 교차로)를 클릭
4. **정렬 3/4**: (자동으로 클릭 통과 모드로 전환됨) Emme4 화면에서 기준점 1과
   동일한 지점(같은 A 교차로)을 클릭 — 이 클릭은 Emme4에도 그대로 전달되므로
   Emme4에서 해당 지점이 선택/클릭되는 것은 정상입니다
5. **정렬 4/4**: Emme4 화면에서 기준점 2와 동일한 지점(같은 B 교차로)을 클릭
   → 배율/위치가 자동 계산되어 오버레이가 즉시 맞춰지고, 클릭 통과 모드로 유지됩니다
6. 언제든 `Esc`로 정렬을 취소할 수 있습니다(진행 중이 아닐 때는 `Esc`가 평소처럼
   Emme4로 전달됩니다)

이 방식은 순수 이동+배율(회전 없음)만 계산하므로, 캡처한 지도 이미지와 Emme4 화면이
회전 없이 같은 방향(북쪽이 위)으로 정렬돼 있다는 전제가 필요합니다.

설정(이미지 경로, 배율, 위치, 투명도, 회전각, 회전 기준점, 고정 상태)은 종료 시
(`Ctrl+Alt+Q`) `MapOverlay.ini`에 저장되어 다음 실행 때 그대로 복원됩니다.
(정렬/회전기준점 지정 "진행 중" 상태 자체는 세션 간 저장되지 않습니다.)

## 회전 (`Ctrl+Alt+P`로 기준점 지정 후 `Ctrl+Alt+[` / `]`)

지도 이미지가 Emme4 화면과 완전히 같은 방향(북쪽이 위)이 아니라 살짝 틀어져
캡처된 경우, 특정 지점을 축으로 이미지를 회전시켜 맞출 수 있습니다.

1. **회전각이 0도인 상태**에서 `Ctrl+Alt+P` 입력 → 편집 모드로 전환되고 회전 기준점
   지정 대기 상태가 됨
2. 지도 이미지 위에서 회전축으로 삼을 지점(예: 교차로)을 클릭
3. `Ctrl+Alt+[` (반시계) / `Ctrl+Alt+]` (시계) 로 1도씩, `Ctrl+Alt+Shift+[` / `]`로
   10도씩 회전 — 회전하는 동안 **기준점은 화면상 같은 위치에 고정된 채** 지도만 돌아갑니다
4. 원하는 각도로 맞춰지면 그대로 편집을 마치거나, 참조점 정렬(`Ctrl+Alt+R`)로 미세 조정
5. `Ctrl+Alt+0`으로 언제든 회전을 초기화(0도)할 수 있습니다. **기준점을 다시(다른 지점으로)
   지정하려면 먼저 회전을 0도로 되돌려야 합니다** — 구현을 단순하고 안정적으로 유지하기
   위한 제약입니다

**동작 방식**: 이 기능은 AHK에 내장된 기능이 아니라, Windows의 그래픽 엔진인 GDI+를
직접 호출해서 회전된 이미지를 임시 파일(`%Temp%\MapOverlay_rotated.png`)로 매번 새로
렌더링한 뒤 불러오는 방식입니다. 항상 원본 이미지에서 다시 렌더링하므로 회전을 여러 번
반복해도 화질이 누적으로 나빠지지는 않습니다.

**알려진 제약/주의사항**:
- 이미지가 크면 회전 한 번 할 때마다 다시 렌더링하느라 확대/축소보다 더 느리게 느껴질 수 있습니다
- 캔버스를 회전 사각형에 맞춰 확장할 때 생기는 네 귀퉁이의 여백은 투명하게 처리를 시도하지만,
  Picture 컨트롤이 PNG 투명도를 완벽히 지원하지 않을 경우 옅은 흰색 삼각형처럼 보일 수
  있습니다(오버레이 자체가 반투명이라 크게 거슬리지는 않을 것으로 예상하지만, 실제로 이상하게
  보이면 알려주세요)
- **이 기능은 Win32 GDI+ API를 코드에서 직접 호출하는 방식이라 이 세션에서는 실제 실행
  검증을 하지 못했습니다.** 이번에 추가된 기능 중 구조가 가장 복잡해서 오류가 날 가능성이
  평소보다 높습니다 — 아래 검증 체크리스트를 꼭 확인해주시고, 에러가 나면 이전처럼 에러
  창 스크린샷이나 메시지를 그대로 보내주세요

## 고정 (`Ctrl+Alt+L`)

위치·배율·회전을 원하는 대로 맞춘 뒤 `Ctrl+Alt+L`을 누르면:
- 오버레이가 즉시 클릭 통과 모드로 전환되고
- 고정 상태에서는 `Ctrl+Alt+T`(편집 모드 전환), `Ctrl+Alt+R`(정렬), `Ctrl+Alt+P`(회전
  기준점), `Ctrl+Alt+[`/`]`(회전), `Ctrl+Alt+0`(회전 초기화)이 모두 무시됩니다
  (안내 메시지만 표시됨)

다시 `Ctrl+Alt+L`을 누르면 고정이 풀리고 평소처럼 `Ctrl+Alt+T`로 편집 모드에 들어갈 수
있습니다. `Ctrl+Alt+H`(숨김/표시)와 `Ctrl+Alt+Q`(종료)는 고정 여부와 무관하게 항상 동작합니다.
고정 상태도 설정 파일에 저장되어 다음 실행 시 그대로 복원됩니다.

## 이 세션에서 확인한 것 / 확인하지 못한 것

AutoHotkey는 Win32 GUI에 의존하는 Windows 전용 런타임이라, 이 코드를 작성한
리눅스 원격 환경에는 AutoHotkey도 wine도 설치되어 있지 않아 **실제 실행 검증은
하지 못했습니다.** 대신 다음 원칙으로 위험을 낮췄습니다:

- 문서화가 불확실한 트릭(예: Picture 컨트롤 `.Value` 재할당으로 이미지 교체)은 배제하고,
  이미 검증 경로로 쓰인 `CreateOverlay()`를 재사용해 창을 다시 만드는 방식으로 대체
- 드래그 이동 / 방향키 이동 / 기준점 클릭 캡처는 모두 `MouseGetPos`, `GetKeyState`,
  `Gui.Move`/`Gui.GetPos` 같은 표준 AHK 함수만으로 구현(이전 버전에서 쓰던
  `WM_LBUTTONDOWN` 메시지 후킹 + `WM_NCLBUTTONDOWN`/`HTCAPTION` 트릭은 제거).
  좌표를 직접 폴링(`while GetKeyState("LButton","P")`)하는 방식이라 컨트롤 종류나
  메시지 전달 여부에 덜 의존적이라 더 신뢰도가 높습니다.
- 클릭 통과 관련 Win32 스타일(`WS_EX_TRANSPARENT`, 0x20)은 AHK/Win32 커뮤니티에서
  오래 검증된 표준 기법만 사용
- 모든 창 대상 함수는 `mapGui` 객체를 직접 넘기지 않고 `"ahk_id " mapGui.Hwnd`로
  명시해 버전 간 인자 처리 차이의 위험을 줄임
- 확대/축소는 커서 위치를 기준(anchor)으로 배율과 창 위치를 함께 재계산하는 단순한
  좌표 기하 계산만 사용(회전 없는 순수 스케일+이동)
- 가장자리 드래그 크기조정도 같은 원리: 반대쪽 모서리(또는 변의 가운데)를 anchor로
  고정하고, anchor로부터의 거리 비율만큼 배율을 바꿔 재계산(가로세로를 독립적으로
  늘리지 않으므로 항상 종횡비 유지). 드래그 중에는 창(부모)을 먼저 옮긴 뒤 이미지
  (자식 컨트롤)를 맞추는 순서로 처리해, 자식이 아직 안 움직인 부모 경계에 잘려 보이는
  현상을 방지
- 참조점 정렬은 두 점 사이 유클리드 거리 비율로 배율을 구하는 단순 기하 계산만 사용
- **회전은 예외적으로 위험도가 높습니다.** Win32 GDI+ 플랫 API(`GdipLoadImageFromFile`,
  `GdipCreateBitmapFromScan0`, `GdipRotateWorldTransform`, `GdipDrawImageRectI`,
  `GdipSaveImageToFile` 등)를 `DllCall`로 직접 호출하는 방식인데, 이런 저수준 API는
  이 세션에서 실행해볼 방법이 없어 검증되지 않았습니다. 함수 시그니처와 상수값(픽셀
  포맷, PNG 인코더 CLSID 등)은 널리 알려진 고정값을 사용했지만, 실제로 처음 실행할 때
  오류가 날 가능성을 다른 기능보다 높게 보고 있습니다

따라서 **아래 체크리스트로 실제 Windows/Emme4 환경에서 한 번은 직접 검증**해 주세요.
특히 회전 기능은 꼭 먼저 테스트해보시고, 문제가 있으면 알려주시면 바로 수정하겠습니다.

## 수동 검증 체크리스트 (Windows + Emme4에서)

- [ ] 스크립트 실행 시 이미지 선택 창이 뜨고, 이미지를 고르면 오버레이가 반투명하게 표시된다
- [ ] Emme4를 켜고 오버레이 아래에 Emme4 네트워크 창을 배치한 상태에서, `Ctrl+Alt+T`로
      클릭 통과 모드로 전환 → 오버레이가 보이는 상태에서도 Emme4의 링크/노드를 정상적으로
      클릭·드래그·선택할 수 있다
- [ ] 다시 `Ctrl+Alt+T`로 편집 모드 전환 → 오버레이 위에서 좌클릭한 채로 마우스를 끌면
      창이 실시간으로 따라오고, 마우스를 놓으면 그 자리에 멈춘다
- [ ] 편집 모드에서 오버레이 밖(예: 바탕화면, 다른 창)을 클릭한 채로 끌어도 오버레이가
      움직이지 않는다(오버레이 위에서 시작한 드래그만 반응해야 함)
- [ ] 편집 모드에서 오버레이 **모서리 근처**를 클릭한 채로 대각선 바깥쪽으로 끌면,
      반대쪽 모서리는 고정된 채 이미지가 종횡비를 유지하며 커진다(늘어나거나 찌그러지지 않아야 함)
- [ ] 반대로 모서리를 안쪽으로 끌면 같은 방식으로 작아진다
- [ ] **아래쪽 변(모서리가 아닌 가운데 부분)**을 클릭한 채로 아래로 끌면, 위쪽은 고정된
      채 이미지가 좌우로 중앙 정렬을 유지하며 비율대로 커진다(왼쪽/오른쪽 변, 위쪽 변도 동일하게 확인)
- [ ] 가장자리를 잡고 끄는 순간 이미지가 좌상단으로 훅 줄어들었다가 다시 커지는 등의
      튀는 현상 없이, 잡은 지점 → 마우스 방향으로 바로 매끄럽게 커지고 작아진다
- [ ] 오버레이 몸통(가장자리에서 떨어진 안쪽)을 클릭한 채로 끌면 크기 변경 없이 이동만 된다
- [ ] 아래쪽 가장자리를 확대할 생각으로 클릭했는데 실수로 이동(드래그)이 되어버리는
      일이 이전보다 확연히 줄었다(가장자리 인식 범위가 넓어졌는지 확인)
- [ ] 편집 모드에서 방향키를 누르면 오버레이가 1px씩, `Shift+방향키`는 10px씩 이동한다
- [ ] 클릭 통과 모드에서 방향키를 누르면 오버레이는 움직이지 않고, Emme4 쪽에서
      방향키가 평소처럼 동작한다(예: 뷰 이동, 선택 이동 등 Emme4 자체 기능)
- [ ] 편집 모드에서 지도 위 특정 지점에 마우스를 올리고 `Shift+휠`을 굴리면, 그 지점이
      화면상 같은 위치에 고정된 채 이미지가 비율을 유지하며 커지고 작아진다
      (모서리가 아니라 커서 위치 기준으로 확대/축소되는지 확인)
- [ ] 클릭 통과 모드에서 `Shift+휠`을 굴렸을 때 오버레이는 반응하지 않고, 휠 스크롤이
      Emme4 창으로 정상 전달된다(Emme4에 휠 확대 기능이 있다면 그게 동작해야 함)
- [ ] `Ctrl+Alt+Up`/`Down`으로 투명도가 단계적으로 바뀐다
- [ ] `Ctrl+Alt+H`를 누르면 모드(편집/클릭통과)와 무관하게 오버레이가 화면에서 완전히
      사라지고, 다시 누르면 같은 위치·배율로 다시 나타난다
- [ ] `Ctrl+Alt+O`로 다른 이미지를 선택하면 같은 위치에 새 이미지로 오버레이가 다시 생성된다
- [ ] `Ctrl+Alt+Q`로 종료 후 다시 실행하면, 마지막 이미지·위치·배율·투명도가 그대로
      복원된다 (`MapOverlay.ini` 확인)
- [ ] 편집 모드가 아닌 상태에서 `Ctrl+Alt+O`, `Shift+휠`, `Ctrl+Alt+Up/Down`, 방향키를
      눌러도 오버레이 쪽은 아무 일도 일어나지 않는다(의도된 동작, 단 `Ctrl+Alt+T`/
      `Ctrl+Alt+H`/`Ctrl+Alt+Q`는 예외로 항상 동작해야 함)

### 참조점 기반 반자동 정렬 (`Ctrl+Alt+R`) 검증

- [ ] `Ctrl+Alt+R` 입력 시 편집 모드로 전환되고 "정렬 1/4" 툴팁이 뜬다
- [ ] 지도 이미지 위 한 지점(예: 특정 교차로)을 클릭하면 "정렬 2/4"로 넘어간다
      (이때 창이 드래그되어 움직이지 않아야 함)
- [ ] 지도 이미지 위 다른 지점을 클릭하면 자동으로 클릭 통과 모드로 바뀌며
      "정렬 3/4" 툴팁이 뜬다
- [ ] Emme4 화면에서 같은 첫 번째 지점을 클릭하면 그 클릭이 Emme4에도 정상 전달되고
      (예: 해당 노드가 선택됨), "정렬 4/4"로 넘어간다
- [ ] Emme4 화면에서 같은 두 번째 지점을 클릭하면 오버레이의 배율/위치가 자동으로
      바뀌어 두 기준점이 지도-Emme4 화면 상에서 겹쳐 보인다
- [ ] 정렬 완료 후 클릭 통과 모드가 유지되어 바로 Emme4 편집이 가능하다
- [ ] 정렬 1/4~4/4 진행 중 `Esc`를 누르면 즉시 취소되고, 정렬 중이 아닐 때 `Esc`는
      평소처럼 Emme4로 전달된다(Emme4의 취소 동작이 막히지 않아야 함)
- [ ] 정렬 진행 중 `Ctrl+Alt+O`(이미지 교체)를 누르면 무시되고 안내 메시지만 뜬다

### 회전 (`Ctrl+Alt+P`, `Ctrl+Alt+[`/`]`, `Ctrl+Alt+0`) 검증

- [ ] `Ctrl+Alt+P` 입력 시 에러 없이 "회전 기준점으로 쓸 지점을 클릭하세요" 툴팁이 뜬다
- [ ] 지도 이미지 위 한 지점(예: 특정 교차로)을 클릭하면 "회전 기준점 지정 완료" 툴팁이 뜬다
- [ ] `Ctrl+Alt+]`를 몇 번 누르면 이미지가 에러 없이 회전하고, 클릭했던 그 지점이 화면상
      같은 위치에 그대로 있는 것처럼 보인다(주변 지형만 그 점을 중심으로 도는 느낌이어야 함)
- [ ] `Ctrl+Alt+[`를 누르면 반대 방향으로 회전한다(방향이 반대로 느껴지면 알려주세요 —
      코드 한 줄만 바꾸면 되는 사소한 문제입니다)
- [ ] `Ctrl+Alt+Shift+]`/`[`로 10도씩 더 크게 회전해도 문제없이 동작한다
- [ ] 회전된 이미지의 네 귀퉁이(빈 삼각형 부분)가 이상하게(예: 새까맣게) 보이지 않고,
      흰색 계열로 은은하게만 보이거나 거의 티가 안 난다
- [ ] 회전 중 `Shift+휠`로 확대/축소, 드래그 이동이 평소처럼 잘 동작한다
- [ ] `Ctrl+Alt+0`을 누르면 회전이 0도로 정확히 돌아오고 이미지가 원래 비율/모양으로 복원된다
- [ ] 회전각이 0이 아닌 상태에서 `Ctrl+Alt+P`를 누르면 "회전각이 0도일 때만..." 안내가
      뜨고 새로 기준점을 지정할 수 없다(먼저 `Ctrl+Alt+0`으로 초기화해야 함)
- [ ] 기준점을 지정하지 않은 상태에서 `Ctrl+Alt+[`/`]`를 누르면 "먼저 Ctrl+Alt+P로..."
      안내만 뜨고 아무 일도 일어나지 않는다
- [ ] 회전각이 0이 아닌 상태로 `Ctrl+Alt+Q`로 종료 후 재실행하면, 회전각과 회전된 모양이
      그대로 복원된다
- [ ] (이미지가 큰 경우) 회전 한 번에 걸리는 시간이 체감상 너무 느리지 않은지 확인 —
      느리면 알려주시면 개선 방법을 찾아보겠습니다

### 고정 (`Ctrl+Alt+L`) 검증

- [ ] 편집 모드에서 `Ctrl+Alt+L`을 누르면 즉시 클릭 통과 모드로 바뀌고 "오버레이 고정됨"
      툴팁이 뜬다
- [ ] 고정 상태에서 `Ctrl+Alt+T`를 눌러도 편집 모드로 들어가지지 않고 안내 메시지만 뜬다
      (오버레이를 클릭해도 이동/크기조정이 전혀 안 되어야 함)
- [ ] 고정 상태에서 `Ctrl+Alt+R`, `Ctrl+Alt+P`를 눌러도 안내 메시지만 뜨고 아무 것도
      시작되지 않는다
- [ ] `Ctrl+Alt+L`을 다시 누르면 고정이 풀리고 "고정 해제됨" 툴팁이 뜨며, `Ctrl+Alt+T`로
      다시 편집 모드에 들어갈 수 있다
- [ ] 고정 상태에서도 `Ctrl+Alt+H`(숨김/표시)는 정상 동작한다
- [ ] 고정 상태로 `Ctrl+Alt+Q` 종료 후 재실행하면 고정 상태가 그대로 유지된다

## 알려진 제한 / 다음 단계 아이디어

- 참조점 정렬(`Ctrl+Alt+R`)은 여전히 이동+배율만 계산(회전 보정 없음) — 회전이 필요하면
  `Ctrl+Alt+P`/`[`/`]`로 먼저 각도를 맞춘 뒤 정렬로 위치/배율을 미세 조정하는 순서를 권장
- 회전 기준점은 한 번에 하나만 유지되며, 다시 지정하려면 회전을 0도로 초기화해야 함
  (여러 기준점을 두고 전환하는 기능은 없음)
- 여러 장의 지도(레이어)를 순환하며 겹쳐 보는 기능
- Emme4 창이 최소화/전환될 때 오버레이를 자동으로 숨기는 옵션(현재는 `Ctrl+Alt+H`로 수동)
- 방향키 미세 이동은 항상 전역으로 등록되어 있어(편집 모드가 아니면 아무 동작 안 함),
  혹시 Emme4에서 방향키 관련 이상 동작이 관찰되면 알려주시면 단축키를 다른 조합으로 변경하겠습니다
- 캡처한 지도 이미지의 해상도가 매우 크면(예: 수천 픽셀급 스크린샷), 반투명 창을
  계속 옮기는 동안 Windows가 매번 알파 합성을 다시 계산해야 해서 드래그/크기조정이
  다소 무겁게 느껴질 수 있습니다. 여전히 랙이 느껴지면, 이미지 자체를 적당한 해상도로
  한 번 축소해두는 것도 도움이 됩니다 — 필요하면 자동 다운스케일 로직을 추가해드릴 수 있습니다
